01 What it does

One clean, correctly-located image per plot — ready to count.

Point Plot Extractor at a georeferenced Metashape project and a plot-boundary shapefile. For every plot it back-projects the boundary into the drone imagery, picks the sharpest near-nadir frame, and writes a tidy upright crop — plus a matching deskewed orthomosaic crop. Crops are snapped to the seven planted rows and radiometrically seam-matched, so each file is exactly one plot.

Per-plot raw crops

Native-resolution pixels from the best frame, deskewed to an upright strip — far sharper than the ortho.

Auto-fit to rows

Detects the crop rows and trims to exactly the planted band — recovering rows the grid clipped.

Gap-fill + seam match

Fills a frame's missing edge from a neighbour and matches brightness & contrast — no visible seam.

Ortho fallback

Field-edge plots with no usable raw frame are rebuilt automatically from the orthomosaic.

Orthomosaic crops

Deskewed, masked, georeferenced — whole-plot nadir geometry alongside the raw.

Plot editor

Nudge, widen and align boundaries over the imagery, with a live width × length read-out.

02 Before you start

Everything below is already installed on the DPIRD workstation.

You'll need

  • A Metashape project (.psx) — aligned, georeferenced, with a DEM and orthomosaic.
  • A plot-boundary file (.shp or .geojson, any CRS).
  • The raw image folder (e.g. the T1_Proc\JPEG folder).
  • A valid Metashape licence (floating server — already configured).

Launch it

Double-click PlotExtractor.bat in the Conversion\PlotExtractor folder.

The window remembers your last settings, so a repeat run only needs the paths changed.

Good to know No Metashape? Switch Source to Orthomosaic GeoTIFF and crop plots straight from an ortho raster — no project and no licence required (ortho crops only).

04 Step-by-step run

A full extraction from a Metashape project — the numbers refer to the window above.

  1. Launch the app

    Double-click PlotExtractor.bat. The window opens with your last settings.

  2. Set the Source 1

    Leave it on Metashape project (use Orthomosaic GeoTIFF only if you have no project).

  3. Choose the project 2

    Click Browse… and select your .psx.

  4. Pick the chunk 3

    The dropdown fills with the project's chunks. Choose the right flight — e.g. RootPheno_Day1. This matters when one project holds several days.

  5. Load the plot boundaries 4

    Browse to your .shp / .geojson. The Plot ID dropdown 5 auto-fills; leave CRS on auto unless the file has no projection.

  6. Point at the raw images 6

    Select the folder of source photos (e.g. the JPEG\Day1 folder). These take priority over the project's own photo paths.

  7. Choose an output folder 7

    An empty or new folder. It will receive RawCrops\, OrthoCrops\ and manifest.csv.

  8. Set options 8

    Margin 0 · Format JPEG (small files) · Quality 100 for near-lossless small files. Use Limit = 10 for a quick test first.

  9. Pick outputs & style 9

    Tick Raw image crop and Orthomosaic crop. Set style to Rectified rectangle (required for auto-fit).

  10. Colour & cores 10

    Tick Convert to sRGB if the source is Adobe RGB (Capture One JPEGs). Leave CPU cores on a comfortable number (16–32 is plenty).

  11. Turn on Auto-fit 11

    Tick Auto-fit crop to detected rows, set rows/plot = 7, mode = width_shift.

  12. (Optional) Align boundaries

    Click Edit plots… to nudge or widen the grid over the imagery, then Save & use. See §7.

  13. Run 12

    Click Run extraction. The log streams each plot live; crops appear in RawCrops\ as they finish.

  14. Review

    Click Open output folder, spot-check a few crops, and scan manifest.csv for any plot flagged in the note column.

Tip Always do a Limit = 10 test run first. Confirm the crops look right, then set Limit back to 0 for the full trial.

06 Auto-fit to rows

Snaps every crop to the planted band — even recovering rows the grid clipped.

With a plot grid, boundaries rarely sit perfectly on the rows. Auto-fit renders each crop wider than the grid, detects the crop rows from the tillage-ridge pattern (works even before emergence), then trims to exactly your rows/plot — so no row is left out and no neighbour's row creeps in.

ModeWhat it doesUse when
width_shiftFits width and recentres on the actual rows.default — offset grids
widthFits width, keeps the grid's centre.well-centred grids
width_lengthAlso trims the along-row ends.rarely
rows/plot Set this to your trial's row count (e.g. 7). Leave it 0 to auto-detect the number. It's per-trial — change it for a different layout.
Automatic safeguards If a plot is too incomplete to read (a field-edge plot with no good frame), Auto-fit skips it and the app rebuilds it from the orthomosaic instead — a complete, correctly-located crop. Gap-fill seams are brightness- and contrast-matched so there's no visible join.

08 Reading the output

Each run writes RawCrops\, OrthoCrops\ and a manifest.csv with one row per plot.

ColumnMeaning
plot_idPlot identifier (from your ID attribute).
plot_area_m2True polygon area of the plot.
raw_image · raw_fileSource frame label and output file name.
crop_w · crop_hOutput crop size in pixels.
raw_covered_pctHow much of the plot the raw crop actually images (100 = complete).
frames_used1 = single frame (seamless); 2+ = gap-filled & seam-matched.
seam_y_pctWhere the frame seam sits (for spot-checking), if any.
fit_rowsRows detected by Auto-fit.
fit_width_m · fit_length_m · fit_area_m2Fitted crop size and area covering the rows, in metres.
ortho_covered_pctOrtho crop completeness.
noteFlags — e.g. ortho-fallback for a field-edge plot. Scan this column.
Colour & brightness Crops keep their natural radiometry — brightness varies plot-to-plot because oblique frames show deeper furrow shadows. For counting, use per-plot adaptive/Otsu thresholding, which handles this without altering the pixels.

09 Troubleshooting

The most common messages and what to do.

You seeCause & fix
“No valid Metashape licence”Licence server unreachable (VPN / network). Reconnect and retry.
“plots are ~X km from the project centre”Wrong CRS or wrong .psx. Check the project, or set the Plot CRS EPSG code.
“raw file missing”Set the Raw images folder to where the photos actually live.
Crop looks like the wrong dayWrong Chunk. Pick the correct sub-project (e.g. Day 2).
note: low coverage / ortho-fallbackField-edge plot with no good raw frame — the app rebuilt it from the ortho automatically. Expected; the crop is complete but softer.
Some plots look darkerNatural furrow-shadow from oblique frames — not an error. Use adaptive thresholding downstream.
Ortho reads are slowUse Make tiled copy once to convert a striped orthomosaic to a fast tiled version.
